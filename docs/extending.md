# Extending adder

A repository extends adder by building its own adder, with Go code of its own: **packs**, which share configuration and templates between repositories, **functions** for templates, and **scanners** for input adder cannot read. All three come in through one type, `adder.Pack`, passed to `adder.Main`.

## Your own build

The build is a `main` package in the repository, declared as a tool in place of adder's:

```go
// tools/adder/main.go
package main

import (
	"typhonhill.dev/adder"

	"example.com/acme/adder-packs/registry"
)

func main() {
	adder.Main(registry.Pack, adder.Pack{Name: "local", Funcs: funcs, Scanners: scanners})
}
```

```sh
go mod edit -droptool typhonhill.dev/adder/cmd/adder
go get -tool ./tools/adder
go tool adder derive
```

`go tool adder` now runs the repository's build, which the Go command caches after the first run. A configuration that uses a pack the build lacks reports `unknown-pack`, and a scan naming a scanner it lacks reports `unknown-scanner`.

## Packs

A pack is a set of scans, outputs, generators, and templates, written once and used by any number of repositories, or several times by one. It is a Go package that embeds a `pack.yaml` and its templates, and is versioned like any other dependency:

```go
// registry/pack.go
package registry

import (
	"embed"

	"typhonhill.dev/adder"
)

//go:embed pack.yaml templates
var files embed.FS

var Pack = adder.Pack{Name: "registry", FS: files}
```

`pack.yaml` has the same `derive`, `generators`, and `partials` as `adder.yaml`, and declares the `options` each use gives. Its [JSON Schema](../schema/pack-v1.json) is `# yaml-language-server: $schema=https://raw.githubusercontent.com/typhonhilldev/adder/main/schema/pack-v1.json`:

```yaml
# registry/pack.yaml
version: 1
options:
  dirs: {type: list, help: "Directories that each hold one package, such as caches/*"}
  package: {help: Directory and package name of the registry, pattern: "[a-z][a-z0-9]*"}
derive:
  scans:
    Entries:
      dirs: {option: dirs}
      funcs: {exported: true, name: ^New$}
  outputs:
    - template: templates/registry.go.tmpl
      path: "{{ .Options.package }}/registry.gen.go"
```

A repository names each use under `packs`, with its options under `with`:

```yaml
# adder.yaml
packs:
  caches: {pack: registry, with: {dirs: ["caches/*"], package: caches}}
  queues: {pack: registry, with: {dirs: ["queues/*"], package: queues}}
```

- **Options** take the settings of generator inputs, `help`, `default`, `pattern`, `values`, and `deprecated`, with `type` `string`, `bool`, or `list`. An option without a default is required, except a bool, which is `false`. A use that gives a deprecated option is warned at its `with` line, so a deprecated string or list option needs a default.
- **In `pack.yaml`**, a mapping whose only key is `option`, such as `dirs: {option: dirs}`, takes that option's value. Templates and paths read options as `.Options`.
- **A pack's templates** see its own scans, `.Options`, and `.Module`, but not the repository's scans or `vars`. Template paths are relative to the pack's `FS`. Scan directories and output paths are relative to the repository root.
- **Each use** runs its own scans, and its outputs are marked `Code generated by adder from templates/registry.go.tmpl in pack registry for caches.`
- **A pack's generators** become `adder new` commands. Two uses of a pack with generators need `rename: {driver: cache-driver}` on one of them. A use tests them with golden files in the repository: `tests: {driver: [{name: plain, inputs: {name: example}, want: testdata/driver}]}`.
- **The repository's own outputs** and generator files can render a pack's template with `pack: registry` next to `template`, using the repository's data, without a use.
- A use changes nothing beyond its options and names. A repository that needs more writes its own outputs or forks the pack.

See [`examples/shared-pack`](../examples/shared-pack).

### Publishing and upgrading

A pack is published like any Go module, and several packs can share one module. Each repository upgrades on its own schedule, and `go.sum` verifies the pack like any other dependency:

```sh
go get example.com/acme/adder-packs@v1.2.0
go tool adder check    # exits 3 if the new version changes what derive writes
go tool adder derive
```

To test a pack, keep a repository that uses it under `testdata` in the pack's module, with tests for its generators under the use.

## Functions

`Funcs` adds template functions, available to every template, the repository's and every pack's:

```go
adder.Pack{Name: "local", Funcs: map[string]any{
	"routeName": func(s string) string { return "/" + strings.ToLower(s) },
}}
```

Functions must be deterministic: the same arguments always give the same result. A name that is built in, or used by another pack, is an `invalid-pack` problem.

## Scanners

`Scanners` adds scanners, for input no built-in scan reads, such as routes registered in a call chain or a file format adder does not know:

```go
adder.Pack{Name: "local", Scanners: map[string]adder.Scanner{"env-file": envFile}}

func envFile(ctx context.Context, in *adder.ScanInput) ([]any, error) {
	var opts struct {
		Files []string `yaml:"files"`
	}
	if err := in.Decode(&opts); err != nil {
		return nil, err
	}
	var items []any
	for _, file := range opts.Files {
		// Read file from in.FS, and append an item per setting, or return an adder.Problem.
	}
	return items, nil
}
```

```yaml
scans:
  Settings:
    scanner: {name: env-file, with: {files: [config/defaults.env]}}
```

- `scanner` takes the place of `funcs`, `types`, `values`, or `files`. `dirs` is optional, expanded as for any scan into `in.Dirs`.
- `in.FS` is the repository, including the files `adder new` is about to write. `in.Decode` decodes `with`, rejecting unknown fields at their place in `adder.yaml`.
- Items are structs, pointers to structs, or `map[string]any`, in an order that depends only on the files. Templates, `each`, `valuesFrom`, `unique`, `sortBy`, and `groupBy` read their fields by name.
- An `adder.Problem`, with a file, line, message, and hint, or several joined with `errors.Join`, is reported at its file with the code `scanner`. Any other error is reported at the scan.
- A scanner must not write files or read anything but `in.FS`, so that `adder check` and `adder derive` agree.

See [`examples/custom-scanner`](../examples/custom-scanner).

## Deprecating what a pack defines

A pack replaces a function or scanner without breaking the repositories that use it by deprecating the old one with `Deprecated`, which says what to use instead:

```go
adder.Pack{
	Name:       "local",
	Funcs:      map[string]any{"pluginTitle": title, "title": title},
	Deprecated: map[string]string{"pluginTitle": "use title"},
}
```

The function keeps working, and every repository whose templates call it is warned at the call:

```text
templates/registry.go.tmpl:12:14: warning: function "pluginTitle" is deprecated: use title [deprecated]
```

A deprecated scanner is reported at each scan that names it. Generators and options in `pack.yaml` are deprecated with `deprecated`, as in a repository's [own](configuration.md#generators).
