# adder

[![CI](https://github.com/TyphonHill/adder/actions/workflows/ci.yml/badge.svg)](https://github.com/TyphonHill/adder/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/TyphonHill/adder.svg)](https://pkg.go.dev/github.com/TyphonHill/adder)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

Write the pattern once. adder adds the rest.

adder generates and maintains the repeated pieces of a Go repository: the registries, wiring, and boilerplate that follow from conventions your team already has. You describe them once in `adder.yaml` with ordinary Go templates, and adder keeps them in step with your code.

> **Status:** early development. `adder derive` and `adder check` work today; the configuration format may still change before v1.0.0.

## How it works

`adder derive` runs in two steps:

1. **Scan.** adder parses the Go files in the directories you name and collects the functions and methods that match your filters, such as "exported and named `New`". It only reads the source; nothing is compiled or run.
2. **Render.** Each list of matches is passed to your templates under the name you gave it, and adder writes the result.

Change your code, run `adder derive` again, and the generated files follow.

## Install

adder supports the two most recent Go releases (currently Go 1.26 and later). Add it as a tool dependency of your module:

```sh
go get -tool github.com/TyphonHill/adder/cmd/adder
go tool adder --help
```

Or install the binary:

```sh
go install github.com/TyphonHill/adder/cmd/adder@latest
```

## Quick start

Say your storage library has one package per driver under `drivers/`, and each exports a `New` constructor:

```
drivers/
  local/local.go   // func New(config map[string]string) (driver.Driver, error)
  s3/s3.go         // func New(config map[string]string) (driver.Driver, error)
```

Instead of keeping a list of drivers up to date by hand, tell adder where to find them. This `adder.yaml` at the repository root defines a scan named `Drivers`, which collects every exported function named `New` in the packages under `drivers/`, and an output that renders a template with that list:

```yaml
version: 1
derive:
  scans:
    Drivers:
      dirs: ["drivers/*"]
      funcs:
        exported: true
        name: ^New$
  outputs:
    - template: templates/drivers.go.tmpl
      path: drivers/drivers.gen.go
```

The template reads the matches through `.Drivers`, the name of the scan. Each match has fields such as `.Name` and `.Package`, the directory it was found in:

```gotemplate
package drivers

import (
	"{{ .Module }}/driver"
{{- range .Drivers }}
	"{{ $.Module }}/drivers/{{ .Package }}"
{{- end }}
)

// All maps each driver name to its constructor.
var All = map[string]driver.Factory{
{{- range .Drivers }}
	"{{ .Package }}": {{ .Package }}.New,
{{- end }}
}
```

Then run:

```sh
$ go tool adder derive
created    drivers/drivers.gen.go
```

```go
// Code generated by adder from templates/drivers.go.tmpl. DO NOT EDIT.

package drivers

import (
	"example.com/storage/driver"
	"example.com/storage/drivers/local"
	"example.com/storage/drivers/s3"
)

// All maps each driver name to its constructor.
var All = map[string]driver.Factory{
	"local": local.New,
	"s3":    s3.New,
}
```

Running it again reports `unchanged` and leaves the file alone. Add a `drivers/gcs` package and the registry follows. This example is the test fixture in [`internal/derive/testdata/basic`](internal/derive/testdata/basic).

## Commands

| Command | Description |
| --- | --- |
| `adder derive` | Run every scan and rewrite the derived outputs that changed. |
| `adder check` | Report derived outputs that are out of date, without writing anything. Exits with status 3 when any are, so CI can catch a forgotten `adder derive`. |

Global flags:

| Flag | Default | Description |
| --- | --- | --- |
| `--root` | `.` | Repository root that scans and outputs are relative to. |
| `-c`, `--config` | `<root>/adder.yaml` | Configuration file. Template paths resolve against its directory. |

`derive` flags:

| Flag | Description |
| --- | --- |
| `-n`, `--dry-run` | Show what would change without writing anything. |
| `--out <dir>` | Write outputs under another directory instead of the root, for example to diff them. |

### Errors and exit codes

Problems are reported with their location and a stable code, and adder reports every problem it finds rather than stopping at the first:

```
templates/drivers.go.tmpl:12:4: <.Drivrs>: map has no entry for key "Drivrs" [template-exec]
	hint: available fields: Drivers, Module
```

| Exit code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | adder ran and found a problem. |
| `2` | adder was invoked incorrectly, such as an unknown flag. |
| `3` | `adder check` found outputs that are out of date. |

See [docs/design.md](docs/design.md#4-structured-diagnostics) for the full list of codes.

## Configuration

### Scans

Each entry under `derive.scans` selects function and method declarations. Its name becomes the template field that holds the results, so it must be a valid Go identifier.

| Field | Description |
| --- | --- |
| `dirs` | Directories to scan, relative to the repository root and written with forward slashes. Glob patterns such as `drivers/*` are allowed. Subdirectories are not scanned. |
| `includeTests` | Also scan `_test.go` files. Defaults to `false`. |
| `funcs.exported` | Only match exported names. |
| `funcs.firstParam` | Only match declarations whose first parameter has this name. |
| `funcs.name` | Only match names containing a match for this regular expression. |

Every match is an item with these fields, sorted by name:

| Field | Description |
| --- | --- |
| `.Name` | Declared name. |
| `.Receiver` | Receiver type for methods, empty for functions. |
| `.Package` | Package name from the file's `package` clause. |
| `.Dir` | Directory relative to the root. |
| `.File` | File path relative to the root. |

### Outputs

Each entry under `derive.outputs` renders one `template` to one `path`. Template paths are relative to the directory holding `adder.yaml`, and output paths are relative to the repository root. Both use forward slashes and must stay inside their root. Nothing is written unless every output renders.

Go outputs are formatted with `gofmt` and marked as generated with Go's [standard header](https://go.dev/s/generatedcode), so editors, linters, and code review tools treat them as generated:

```go
// Code generated by adder from templates/drivers.go.tmpl. DO NOT EDIT.
```

If a template already writes its own `// Code generated ... DO NOT EDIT.` line, adder keeps it as is.

Templates also receive `.Module`, the module path from the root's `go.mod`. Referencing a field that does not exist is an error, so typos fail loudly.

### Template functions

adder provides a small set of deterministic functions alongside Go's [built-in template functions](https://pkg.go.dev/text/template#hdr-Functions). Names follow [Sprout](https://github.com/go-sprout/sprout) where it has an equivalent.

| Function | Example | Result |
| --- | --- | --- |
| `toLower`, `toUpper` | `toUpper "abc"` | `ABC` |
| `toCamelCase` | `toCamelCase "user_id"` | `userId` |
| `toPascalCase` | `toPascalCase "user_id"` | `UserId` |
| `toSnakeCase` | `toSnakeCase "HTTPServer"` | `http_server` |
| `toKebabCase` | `toKebabCase "HTTPServer"` | `http-server` |
| `toConstantCase` | `toConstantCase "HTTPServer"` | `HTTP_SERVER` |
| `toGoCamelCase` | `toGoCamelCase "user_id"` | `userID` |
| `toGoPascalCase` | `toGoPascalCase "user_id"` | `UserID` |
| `fieldValues` | `fieldValues "Package" .Drivers` | the `Package` field of every item |
| `uniq` | `uniq (list)` | values with repeats removed, in first-seen order |
| `sortAlpha` | `sortAlpha (list)` | values sorted alphabetically |

Case functions split words at separators such as `_`, `-`, and spaces, at lowercase-to-uppercase changes, and at the end of an acronym: `HTTPServer` is `HTTP` and `Server`. The Go variants produce identifiers that follow Go naming style: they keep words already in capitals, such as `BMC`, and capitalize common initialisms such as `ID`, `HTTP`, and `URL`.
