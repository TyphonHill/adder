# adder

[![CI](https://github.com/typhonhilldev/adder/actions/workflows/ci.yml/badge.svg)](https://github.com/typhonhilldev/adder/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/typhonhill.dev/adder.svg)](https://pkg.go.dev/typhonhill.dev/adder)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

**Go boilerplate that maintains itself.**

adder writes the repetitive parts of a Go repository, such as registries, route tables, and wiring, from the code they describe, and keeps them current as that code changes. It also creates new code from your own templates, so every new package starts the same way.

1. Describe a pattern once in `adder.yaml`: the code to scan, and a Go template.
2. `adder derive` writes the files. `adder new` adds new code and updates them in the same run.
3. `adder check` fails CI when a generated file falls behind the code.

## Example

Every package under `drivers/` has a `New` function, and `drivers.All` constructs each of them. Instead of keeping that list by hand, describe it once:

```yaml
# adder.yaml
version: 1
derive:
  scans:
    Drivers:
      dirs: ["drivers/*"]
      funcs: {exported: true, name: ^New$}
  outputs:
    - template: templates/registry.go.tmpl
      path: drivers/drivers.gen.go
```

```gotemplate
// templates/registry.go.tmpl
package drivers

import (
	"{{ .Module }}/storage"
{{- range .Drivers }}
	"{{ .ImportPath }}"
{{- end }}
)

// All returns a new instance of every driver, by package name.
func All() map[string]storage.Driver {
	return map[string]storage.Driver{
{{- range .Drivers }}
		"{{ .Package }}": {{ .Package }}.New(),
{{- end }}
	}
}
```

`adder derive` writes `drivers/drivers.gen.go`, formatted, with the imports it uses and Go's generated-code header:

```go
// Code generated by adder from templates/registry.go.tmpl. DO NOT EDIT.

package drivers

import (
	"example.com/registry-from-functions/drivers/disk"
	"example.com/registry-from-functions/drivers/memory"
	"example.com/registry-from-functions/storage"
)

// All returns a new instance of every driver, by package name.
func All() map[string]storage.Driver {
	return map[string]storage.Driver{
		"disk":   disk.New(),
		"memory": memory.New(),
	}
}
```

A [generator](docs/configuration.md#generators) creates new drivers that are registered as soon as they exist, and `adder check` catches one added by hand without `adder derive`:

```console
$ adder new driver name=s3
created    drivers/s3/s3.go
updated    drivers/drivers.gen.go
$ adder check
would be updated    drivers/drivers.gen.go
adder: 1 derived file is out of date; run 'adder derive' to update it
```

The [registry-from-functions](examples/registry-from-functions) and [scaffold-with-generator](examples/scaffold-with-generator) examples are complete repositories that do this.

## Features

- **Scans** of functions, types, constants, and files, selected by name, signature, [comment directive](examples/routes-from-directives), or [the type checker](examples/types-implementing-interface).
- **Any output**: Go, [one Markdown page per item](examples/file-per-item), SQL, YAML, each with a generated-code header in its own comment syntax. Files that are no longer produced are removed.
- **Generators** with validated inputs, prompts in a terminal, dry runs, and [golden-file tests](examples/scaffold-with-generator).
- **Packs** share scans, outputs, and generators [between repositories](examples/shared-pack), versioned as Go modules.
- **Extensible** with your own template functions and [scanners](examples/custom-scanner) written in Go.
- **Monorepos**: [`adder check ./...`](examples/monorepo) checks every `adder.yaml` at once.
- **Built for [CI](docs/integrations.md) and [agents](docs/agents.md)**: `--json` on every command, stable problem codes, and a JSON Schema for each generator's inputs.
- **Safe**: adder never overwrites a file it did not generate, writes nothing unless everything succeeds, and gives the same output on every machine.

## Install

adder supports the two most recent Go releases. Add it as a tool of your module, and run it with `go tool adder`:

```sh
go get -tool typhonhill.dev/adder/cmd/adder
go tool adder init
```
