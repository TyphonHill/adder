# Shared pack

This example shows a pack: a set of scans, outputs, and templates, written once and used several times with different options. Here one pack builds a registry of packages, and the repository uses it twice, once for caches and once for queues. Without a pack, each registry would need a copy of the same scan, output, and template.

## How it works

- [`registry/`](registry) is the pack. [`pack.yaml`](registry/pack.yaml) declares two options, `dirs` and `package`, and uses them: `dirs: {option: dirs}` fills the scan's directories with the option's value, and the output's path reads `{{ .Options.package }}`. Its template, [`registry.go.tmpl`](registry/templates/registry.go.tmpl), reads options in the same way.
- [`registry/pack.go`](registry/pack.go) embeds `pack.yaml` and the templates in an `adder.Pack`. In a real project, the pack would be a module of its own, which other repositories require like any dependency.
- [`tools/adder/main.go`](tools/adder/main.go) builds this repository's own adder with the pack, through `adder.Main(registry.Pack)`. [`go.mod`](go.mod) declares it as a tool, so `go tool adder` runs it at the version `go.mod` pins.
- [`adder.yaml`](adder.yaml) has two uses of the pack under `packs`, `caches` and `queues`, each with its own options under `with`. It declares no scans or outputs of its own:

```yaml
packs:
  caches:
    pack: registry
    with: {dirs: ["caches/*"], package: caches}
  queues:
    pack: registry
    with: {dirs: ["queues/*"], package: queues}
```

Each use derives its own file, [`caches/registry.gen.go`](caches/registry.gen.go) and [`queues/registry.gen.go`](queues/registry.gen.go), and its header names the pack and the use: `Code generated by adder from templates/registry.go.tmpl in pack registry for caches.`

## Try it

Run the commands from this directory:

```console
$ go tool adder derive
$ go run ./cmd/demo
caches: [disk memory]
queues: [inmemory]
```

[`go.work`](go.work) builds the example with adder from this checkout, so it always matches the adder it documents. A repository of your own requires `typhonhill.dev/adder` in `go.mod` instead, and has no `go.work`.

A pack can also share generators, template functions, and custom scanners. See [`custom-scanner`](../custom-scanner) for a scanner.
