# One file per item

This example shows an output with `each`, which renders its template once per scan item and writes one file for each. Here every configuration section, an exported struct in [`config/config.go`](config/config.go), gets its own reference page under [`docs/config/`](docs/config), listing its fields. The pages are Markdown, which shows that derived files do not have to be Go.

When a section is removed, its page is removed too: adder knows which files it derived, so no stale page is left behind.

## How it works

- [`adder.yaml`](adder.yaml) declares the `Sections` scan with `types: {kind: struct, exported: true}`, which selects exported struct types rather than functions. The unexported `duration` is left out.
- The output names its scan with `each: Sections`, and its `path` is a template too, so every item gets its own file: `docs/config/{{ .Item.Name | toKebabCase }}.md`.
- [`templates/section.md.tmpl`](templates/section.md.tmpl) renders one item, `.Item`, and ranges over its `.Fields`, each with a `.Name`, `.Type`, and `.Tag`. [`docs/config/server.md`](docs/config/server.md) is one result:

```markdown
<!-- Code generated by adder from templates/section.md.tmpl. DO NOT EDIT. -->
# Server

Server configures the HTTP server.

| Field | Type | Tag |
| --- | --- | --- |
| `Addr` | `string` | `yaml:"addr"` |
| `ReadTimeout` | `time.Duration` | `yaml:"readTimeout"` |
| `WriteTimeout` | `time.Duration` | `yaml:"writeTimeout"` |
```

adder writes the "generated" header in the comment syntax of each file type, here an HTML comment for Markdown.

## Try it

Run the commands from this directory, with `go run ../../cmd/adder` in place of `adder` in a checkout of adder. Delete the `Logging` struct from `config/config.go`, and its page is reported, then removed:

```console
$ adder check
would be removed    docs/config/logging.md
adder: 1 derived file is out of date; run 'adder derive' to update it
$ adder derive
removed    docs/config/logging.md
```

Adding a struct adds its page in the same way.
